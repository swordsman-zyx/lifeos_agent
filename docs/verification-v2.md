# 第二版验证记录

日期：2026-11-01。本文已更新为函数式节点、仅模型驱动的实现。

## 当前实现

- `nodes.py` 为普通函数，`workflow.py` 显式注册节点和边。
- `FoodContext` 通过 `Runtime` 注入模型、MCP 客户端和 Repository，执行与恢复均传入上下文。
- 应用不含无密钥规则模式、餐品关键词解析、预设规格匹配或自动回退。
- 缺少模型密钥时启动失败；模型调用失败时返回明确提示，不生成预设订单。
- 按项目设计保留独立的模拟外卖 MCP 平台和模拟支付。

## 自动化验证

`python -m unittest backend.tests.test_flow -v`：13 个测试通过。

- MCP 查询、设置购物车、人工确认和提交订单的函数节点流转。
- 确认前没有订单，重复确认返回同一订单。
- 取消后不创建订单，旧确认被拒绝。
- 查询结果转换为候选卡片，结构化选择与多轮消息继续传入模型。
- 地址选择与消息请求去重。
- 重建 API、Graph 和 checkpointer 后恢复待确认订单。
- 平台已写入订单但 Graph 尚未完成保存时，恢复并复用原幂等键。
- 响应丢失后查询找回、明确失败、持续未知、处理中转成功及手动查询。
- 工具消息衔接正确，下单工具不向模型暴露。
- 购物车替换、规格参数校验与幂等键冲突。
- 未配置密钥时启动失败，无默认或备用模型。
- 模型不可用时返回失败提示，不创建购物车、确认事项或订单。

测试启动真实 MCP HTTP 子进程，FastAPI 使用 ASGI 测试客户端，两端共用临时 SQLite。模型响应只由 `backend/tests/models.py` 显式注入；替身不解析输入，不被应用代码导入。这些测试验证编排与业务规则，不验证模型对中文需求的理解质量。

代码检查：`python -m ruff check backend delivery_mcp shared`。
前端检查：`npm run build`，包含 TypeScript 检查与 Vite 生产构建。
